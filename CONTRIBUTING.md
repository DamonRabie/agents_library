# Contributing

Contributions should keep this library reusable, attributable, and safe to
publish.

## Before Opening a Pull Request

1. Keep reusable instructions project-neutral.
2. Do not include project codenames, private hostnames, IP addresses,
   usernames, absolute local paths, credentials, or customer data.
3. Update `SOURCES.md` when importing or adapting external material.
4. Preserve license and attribution metadata for derived work.
5. Run the narrowest relevant checks and `git diff --check`.
6. Confirm links and relative symlinks still resolve from the repository root.

## Pull Requests

- Use a focused branch and keep each pull request scoped to one concern.
- Explain what changed, why it belongs in the shared library, and how it was
  verified.
- Do not commit generated artifacts, caches, local environment files, or
  secrets.

Security concerns must follow [SECURITY.md](SECURITY.md) instead of being
reported publicly.
