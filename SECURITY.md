# Security Policy

## Supported Content

Security fixes are applied to the current default branch. Content under
`archive/` is retained as reference material and is not actively maintained;
review it before execution or reuse.

## Reporting a Vulnerability

Do not report vulnerabilities in a public issue.

Use GitHub's private vulnerability reporting flow from the repository's
**Security** tab. Include the affected path, impact, reproduction steps, and
any suggested remediation. Reports will be acknowledged and assessed before
public disclosure.

Never include live credentials, private keys, customer data, or confidential
project information in a report or proof of concept.
